## Installed Codex package verification

The active Windows Codex installation reports
`engineering-board@engineering-board` as installed, enabled, and version
1.13.0. The marketplace snapshot and
`.codex-marketplace-install.json` both resolve
`dcbd3ea10970d1437899607d77a2e4be1ec157af` from the Git repository''s `main`
ref. This commit is also the immutable v1.13.0 tag target.

The installed cache contains five board skills and four migrated command
skills. A direct launcher handshake returned MCP protocol `2025-06-18`, server
version `1.13.0`, and 19 tools. The tool list includes `board_context`,
`board_claim`, and `board_release`.

An installed-runtime smoke test created an isolated board and one high-
confidence Learning. `board_context` surfaced `L001` for a matching `src/`
path and exposed its confidence. `board_status` reported the Learning. The
smoke repository is disposable verification data, not product evidence.

## Local installation limitation

An explicit remove-and-add cycle could not delete the loaded version 1.12.0
cache because an active Codex worker holds a Windows file lock. The add command
also reported a cache-backup error after the version 1.13.0 cache existed. No
worker or Codex host was terminated.

Codex nevertheless selects version 1.13.0, and the exact 1.13.0 cache passed
the manifest, source-revision, skill-count, MCP handshake, and runtime smoke
checks above. The old 1.12.0 cache directory remains inactive storage until a
later app restart releases the lock. This already-running thread retains its
start-of-session capability snapshot; a new Codex process resolves version
1.13.0.
